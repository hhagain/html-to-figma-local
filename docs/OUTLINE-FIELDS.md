# 输入框与按钮 outline 修复（v0.9.3）

## 原因

A-60「创建分组」中的「字段 / 分组名称」使用白色背景、12 px 圆角和 CSS `outline: 1px solid #E5EAF0; outline-offset: -0.5px`。它的轮廓由 outline 绘制，HTML 没有常规 border。

旧版捕获器仅保存 border，遗漏了 outline。输入框的 318 × 48 px 尺寸与「工作」文字仍在，但白色内容框与弹窗白色背景融在一起，看起来像输入框消失。「取消」按钮的蓝色轮廓也受同一问题影响。视觉还原和 Auto Layout 均会遇到这个捕获问题。

## 修复行为

- 支持捕获 outline 的颜色、宽度和偏移。
- 可直接映射的轮廓使用 Figma 原生描边：offset 为 0 对应外侧，负半宽对应居中，负整宽对应内侧。
- 描边不改变捕获到的内容框、圆角或 padding。Auto Layout 排除描边参与布局，保持输入框和文字位置。
- 特殊偏移及 border 与 outline 共存的简单容器使用独立轮廓 Frame，保留两种边线；该容器保留视觉布局，避免装饰层进入 Auto Layout 排列。
- 不支持的线型、裁剪组合或过大的负偏移明确提示。虚线/点线沿用现有虚线转换，复杂样式不保证完全一致。
- v1 数据格式的 `border` 增加可选的 `align` 字段，旧数据未设置时继续使用原来的内侧描边。

## 验证范围

- 类型检查通过，完整自动化测试 **125 / 125** 通过。
- 浏览器解析与导入测试覆盖输入框和取消按钮、视觉/Auto Layout 两种模式、布局重排、圆角、偏移、缩放、border 共存、旧版数据兼容及编译插件 UI 消息链。
- Auto Layout 测试宿主会模拟启用布局时的尺寸重算，检查输入框的 318 × 48 px 尺寸、居中 1 px 描边和内容位置。
- 用户原始大文件完成 **550 / 550** 个对象的 Auto Layout 编译插件测试宿主导入，**0** 失败，恢复 **222** 个 outline；原有内容的捕获坐标和尺寸未改变。A-60 在两种布局模式下均保留 **318 × 48 px**、**12 px** 圆角与 **1 px** 居中描边。
- 自动化测试与浏览器预览不能替代真实 Figma 客户端的最终渲染验收。

## 重测步骤

1. 关闭并重新运行 **HTML to Figma · Local**，确认底部显示 **v0.9.3**。
2. 从原 HTML 重新解析，保持 **自动拆分多页面**，选择 **智能 Auto Layout**。
3. 可以只勾选 **A-60 / 创建分组**，导入后检查名称输入框的灰色圆角轮廓与取消按钮的蓝色轮廓。

旧版 JSON 没有保存这些 outline，需重新解析原 HTML。已有图层不会自动更新。
