# 无状态清单的动态 HTML：自动交互探索

## 使用方式

1. 打开 v0.6.0 桌面助手并同步插件。
2. 在“网页链接”中输入网址或本地 HTML 路径，选择“多状态捕获”。
3. 页面来源保持“自动探索交互（推荐）”，探索深度默认 4 层。
4. 点击“探索交互状态”，等待结果。可随时取消，已经记录的状态会保留。
5. 查看结果中的路径、状态类型和未覆盖统计，勾选需要的状态后捕获。
6. 使用多页预览核对结果，再导入 Figma。

HTML 本身不需要包含 JSON 清单。工具会自动生成每个状态的点击、填写、选择、等待与滚动步骤；“导出已选状态清单”可保存并复用这些步骤。

## 能自动探索的状态

- 主导航和同源页面链接。
- 点击详情、设置、编辑、展开等入口后出现的页面或弹窗。
- 表单初始状态，以及在空白字段中填入少量示例数据但不提交的状态。
- 本地 HTML 中存在空白必填项时的表单校验状态；远程网站不自动提交表单。
- 原生下拉选项、单选、多选和滚动容器的代表位置。

探索从入口独立重放每条路径，不沿用用户浏览器的登录和本地存储。重复视觉内容根据可见文本、控件状态和滚动状态的摘要合并。捕获时再检查摘要；如果页面已变化或无法稳定重放，会报告失败，不将错误状态标作成功。

## 范围与未覆盖项

默认每轮没有固定状态数上限，仍按最多尝试 300 条路径、运行约 3 分钟的预算探索。可选择 3、4、6 层深度。同类列表项最多取两个代表样本，单状态最多生成 45 个动作候选。为避免在全站导航之间循环，重复的全局导航入口只探索一次。

探索报告包含已记录状态、尝试数、重复数、失败路径、跳过控件、待处理数量和部分待处理路径。达到数量、深度或时间上限时明确显示尚有未探索动作。没有“完整覆盖百分比”：用户输入、数据组合、权限、网络失败、长按和时间变化可能产生无限状态。

文件选择、设备权限、敏感账号字段、显式删除/授权/支付控件、已填写表单提交会跳过；HTTP 写请求、跨站导航、WebSocket 和 sendBeacon 会被阻止。网站需要这些能力时，报告可能只覆盖登录前或演示状态。

自动探索不能替代完整业务验收。对需要真实登录、上传图片、长按语音或外部数据的状态，可调整原型为可直接进入的演示状态，或在高级清单中明确设置步骤。当前版本没有交互录制器，也不会声称穷举了所有状态。

## 与导航发现的区别

“仅发现导航页面”适合只需要一级页面的快速任务。“自动探索交互”用于同一地址下仍有详情、弹窗、表单等状态的动态原型。捕获完成的 `N/N` 只表示所选状态的重放结果，不是产品所有状态的数量。
