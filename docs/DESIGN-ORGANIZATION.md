# 产品页面自动分类与分组排版（v0.10.0）

动态探索记录页面如何进入、属于哪个主导航、是否是弹窗/表单、是否仅滚动了同一长页。导入时利用这些关系组织设计画布，减少按捕获先后顺序混排的问题。该功能同时用于导航发现、交互探索与状态捕获，不依赖外部 AI 服务。

## 分类规则

| 分类 | 推断依据 | 典型内容 |
| --- | --- | --- |
| 一级页面 | 已选中的主导航入口 | 首页、明细、计划、资产 |
| 二级页面 | 从所属页进入独立详情或页面路由变化 | 账单详情、分类详情、设置 |
| 功能页面 | 弹窗/表单，或同一功能区域的状态变化 | 新增计划、填写、校验、预算切换 |
| 待确认页面 | 没有可靠导航或进入关系 | 首次打开的无导航独立页面 |

分类是基于可观察结构的推断。点击次数不等于页面层级。列表中显示分类及模块，悬停可查看推断依据；捕获结果的每组旁边提供层级选择器，用户可以调整为一级、二级、功能或待确认页面。

## 排版规则

- 每个模块自成一行区域，一级页面、二级页面、功能页面按列组织；每个页面/功能在 Figma 中形成有名称的 Section。
- 同一长页的滚动截图按滚动位置排序，并排相邻放置，间距 24 px；即使探索顺序被其他页面打断，最终仍会放回一起。
- 同一功能的默认、填写、校验等状态在同一分区内排布。列表中不同记录进入同一详情模板时，按同一详情功能归组。
- 状态较多时在分区内换行；每个状态保持独立、可编辑的 Frame。页面内部的视觉还原与 Auto Layout 仍按所选模式处理。
- 仅勾选部分状态时，只生成有成功页面的分区。取消或单页失败不会移除已完成内容。
- 原 HTML 已有绝对定位大画布时，优先保留原画布坐标。没有分类信息的旧数据沿用既有排列，避免凭名称强行猜测层级。

页面分类保存在可选的 `source.design` 中。原有 v1 捕获数据格式继续兼容；分类随 JSON 备份、勾选、桌面直传和插件批次传递。修改分类后重新发送会使用新的传输标识。

## 使用步骤

1. 更新桌面助手和 Figma 插件到 v0.10.0，并重新打开。
2. 在助手的网页链接入口输入网页或本地 HTML 路径，例如 `file:///…/index.html#/planning`。
3. 选择“多状态捕获 → 自动探索交互”，点击探索，勾选需要的状态后开始捕获。没有 JSON 状态清单也可使用。
4. 在结果列表检查模块和页面类型，需要时直接调整组的层级。
5. 从助手发送/直接导入，或下载捕获 JSON 后在 Figma 插件中导入。分组关系自动跟随数据，不需要在 Figma 中重新设置。

同一批次内的长页分段和功能状态会归组。本功能不自动修改已存在的设计分区；旧捕获结果缺少来源关系时，应重新探索并捕获。

## 验证范围

类型检查与完整自动化回归通过，**138 / 138** 项测试成功。

仓库中的 `examples/product-design-flow.html` 为独立编写的合成回归样例，覆盖主导航、同模板详情、表单、校验和可滚动内容。测试检查：

- 无状态清单探索后，分类与页面进入关系能够随捕获数据保存。
- 滚动分段按顺序相邻排列，同功能的多个状态归入同一分区。
- JSON 备份、桌面传输、部分勾选、单页分类修正和编译插件消息链保留分类。
- 取消、失败、无 Section API 的环境保留已完成页面与已有设计。
- 旧数据与原绝对定位画布沿用其既有排版。

编译插件的自动化导入使用 API 测试宿主，不等同于真实 Figma 桌面客户端的最终渲染验收。自动探索受任务时间、状态和操作预算约束，不保证穷举任意 HTML 的全部状态。

用户本地源文件、捕获数据与实测细节仅保存在忽略的本地 artifacts 目录，不进入公共仓库或分发包。
