# 保留原 HTML 画布排布（v0.9.1）

## 现象与原因

一些设计工具导出的 HTML 是一张大画布：手机页面、色彩规范、分类标题、页签和注释都在同一个容器中绝对定位。文件名可能只包含一个页面名，但文件实际包含整份设计。

旧版自动拆页保留了每页内部的位置和尺寸，却丢失这些页面在父画布中的坐标。批次导入随后按 DOM 顺序、最多八列重新排列，因而会出现色板插入手机页面中间、注释与对应页面分离、行距被大尺寸规范页撑开等问题。

## 修复行为

- 自动拆页时，同一父容器中的两个或更多绝对定位对象记录共同画布 ID、对象坐标和画布范围。
- 画布范围包含滚动内容与对象边界，不只采用可能被 flex-shrink 压缩的容器宽度。
- 逐页捕获继续将每个根 Frame 内部归一到 `(0,0)`；批次导入根据画布信息恢复各根 Frame 的相对位置。
- 整张画布统一平移到现有设计右侧；只勾选部分对象时仍保留它们的原始间距，源文件已有的重叠也会保留。
- 多个 HTML 文件、多个画布和重复导入的 JSON 备份分别放置。普通流式页面、独立动态状态和无画布信息的旧版 JSON 继续自动排列。
- 每页仍是可编辑的独立 Frame，并保留逐页取消、失败记录及现有资源预算。

画布信息位于可选的 `source.canvas` 字段，包含 `id`、`x`、`y`、`width`、`height`。格式版本仍为 1，读取时校验有限坐标、正尺寸和画布 ID。

## 更新与重测

1. 关闭正在运行的 **HTML to Figma · Local**。
2. 若开发插件指向仓库根目录，重新运行即可；若使用 ZIP，解压 `html-to-figma-local-0.9.1.zip`，从新目录的 `manifest.json` 加载。
3. 确认底部版本为 **v0.9.1**。
4. 重新选择原 HTML，保持 **自动拆分多页面** 开启，建议先用 **视觉还原**。
5. 点击 **解析并预览**。检测到此类画布时，转换摘要显示 **保留原画布排布**。
6. 勾选需要的对象，再点击 **导入到 Figma**。旧版 JSON 不含原画布坐标，应从原 HTML 重新解析。

更新不会重排已经导入的节点。HTML 本身的重叠、隐藏内容、字体在 Figma 中不可用或浏览器特效不受支持等问题，需要分别判断。

## 已验证范围

- 类型检查通过，完整自动化测试 **115 / 115** 通过。
- 合成回归样例覆盖 DOM 顺序不同于视觉顺序、尺寸混合的规范页/手机页/页签/注释、源文件重叠、窄视口、多文件、部分勾选及 JSON 重新加载。
- 用户本地约 59 MB 的导出文件：原画布 **3990 × 60901**，**550** 个顶层对象，其中 **180** 个 **390 × 844** 手机 Frame；左上角已有 **46** 个对象重叠。
- 该文件经编译插件 UI 的离线 Tailwind 解析、JSON 导出校验和编译插件消息处理后，在 Figma API 测试宿主中完成 **550 / 550** 对象导入、**0** 失败、**20,531** 个捕获节点，全部顶层坐标和尺寸与原浏览器几何逐一匹配。
- 这些验证覆盖实际源文件和编译插件流程，尚不等于真实 Figma 客户端的字体与最终渲染验收。
- 私有源文件、嵌入字体、捕获 JSON 与测试截图仅保留在本地忽略的 `artifacts/layout-mismatch/`，不进入分发包。
