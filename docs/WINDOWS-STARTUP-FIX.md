# Windows v0.8.1 启动修复

2026-10-26 收到的诊断报告显示，v0.8.0 在加载捕获服务时发生 `ERR_MODULE_NOT_FOUND: Cannot find package 'playwright'`。两个包的 package.json 均不存在；3847–3851 端口可用，应用数据目录写入通过。

## 原因

Windows 打包使用的 electron-builder 26.15.3 在 extraResources 文件复制过滤器中会忽略匹配根部的 node_modules。v0.8.0 以整个 engine 为复制入口，导致其中两项捕获运行依赖被跳过。

原安装验收目录位于构建仓库的 .cache 下，Node 可以沿父目录查找到仓库根部的依赖，掩盖了分发包中的遗漏。此前“无需系统 Node 或浏览器”的验证没有证明包内 JS 依赖完全自包含；这一验收结论需要按新方法修正。

## 修复与验证设计

- 将 playwright 和 playwright-core 分别指定为资源复制项，复制入口直接指向各包目录。
- afterPack 检查依赖入口及解析路径，拒绝使用包目录以外的依赖；生成实际库文件的 SHA-256 清单。
- EXE 安装目录、便携 ZIP 解压目录位于操作系统临时目录，与构建仓库分离。分别校验全部依赖文件并启动捕获服务和应用窗口。
- 启动时检查依赖，避免在缺文件时只显示通用退出码；记录实际 stderr 并提供菜单日志入口。
- v0.8.0 修复补丁只补齐捕获依赖，并在写入前核对补丁内容，适用于现有可写便携目录。

修复不会要求安装 Node.js、npm 或外部浏览器。真实 Windows Figma 文件联调仍需用户设备确认，与安装包自包含检查分别记录。
