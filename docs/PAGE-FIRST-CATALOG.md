# 页面优先与组件目录（v0.14.0）

## 默认流程

1. 先发现并验证主导航、同源页面链接及页面入口。
2. 再探索局部展开、填写、校验、选中等组件状态；出现新页面入口时重新优先处理页面。
3. 捕获时按“页面模板 → 组件状态 → 图标库”的顺序执行。

主导航不参与“同类控件仅取两个”的采样限制，也不会被普通控件候选数量挤掉。报告显示主导航已验证数量和未探索名称。时间、尝试次数、深度与每轮状态预算仍有效；达到预算时保留队列继续，并不宣称所有隐藏页面已覆盖。

## 同结构组件只保留一个

相同列表项、卡片和输入控件按照结构归组，DOM 位置、记录文案和图标差异不会分别创建组件家族。默认“同样式的数据样本”选择“合并为一个代表组件”，保留一个初始组件；真正的展开、填写、错误、禁用和选中状态保留为变体。

需要比较数据样本时仍可主动选择两个或三个样本。纯数据的金额、文字和数据配色会归并。图标自身的差异不作为一套新组件状态，图标资源单独整理。

## 相同表单只保留一个完整页面

同一“新增订阅”等表单或弹窗只保留一个完整模板。支付方式、银行账户、金额、输入文字和校验提示的变化输出局部组件卡片。嵌套日期/图标选择等局部面板不再重复整张父表单。

不同主页面、路由和独立功能表单仍保留必要模板。识别依据导航、结构和可见的表单标题；不依赖源 HTML 自带状态清单，也不是完整的业务语义模型。

## 图标库

页面和组件中的小尺寸 SVG，以及带图标标记的图片，会按图形或资源去重后集中输出到“图标库”。视觉可见、仅用于装饰的 `aria-hidden` 图标也收集。重复图形只保留第一次遇到的外观；SVG 作为可编辑矢量，图片保留图片形式。

Figma 中，页面模板为 Frame，交互组件为原生 Component / ComponentSet；图标作为独立组件放入一个网格图标库。原页面内的图标继续保留，图标库提供额外的复用资源。

## 更新与兼容

同时更新助手和插件到 v0.14.0，从菜单栏或托盘退出旧助手，再打开新版。使用“网页链接 → 多状态捕获 → 自动探索交互 → 设计稿”重新探索、捕获。旧结果不会自动重建组件和图标目录。新版界面连接旧助手时会明确提示更新。

“全部交互状态 · 调试用”保留原来的逐状态方式。API `outputMode: "design"` 默认 `dataSamples: 0`；`artifact.kind` 扩展为 `page` / `component` / `icon`。导航覆盖记录在 `report.navigation` 中。只表示已识别且已验证的导航入口，不等于全部产品页面或权限状态。
