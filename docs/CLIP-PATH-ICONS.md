# CSS 路径图标修复（v0.9.2）

## 原因

用户截图中的倒计时不是 `<img>` 或内联 `<svg>`。原 HTML 用两个纯色 `div` 叠放，分别通过 `clip-path: path(...)` 裁成灰色空心轨道和蓝色/橙色剩余弧线，最后叠放中央数字。

旧捕获器读取了矩形尺寸与背景色，但仅对未支持的 `clip-path` 给出警告，没有保存裁剪路径。导入后留下纯色矩形，中央数字与背景同色，看起来像整个图标丢失。

## 修复

- 无子内容、无边框/圆角/阴影的纯色 CSS `path()` 图形转成 SVG 路径，再使用既有 Figma 原生 SVG 导入流程。
- 保留路径曲线、nonzero/evenodd 填充规则、透明度和原始布局坐标系；CSS 缩放后仍按正确尺寸导入。
- 清除外层矩形的填色，避免遮挡圆环内部。独立的中央数字继续作为可编辑文字导入。
- 图片、画布和表单控件等自带渲染内容的元素不会被误识别为只有背景的图标。
- 其他未支持的裁剪单独显示 `CLIP_PATH_UNSUPPORTED`；滤镜和背景模糊仍按实际能力提示。

当前修复不覆盖任意 CSS 裁剪，例如带子内容的裁剪容器、裁剪图片、渐变或图片背景、`url()`、`circle()`、`polygon()`，也不改变伪元素等现有边界。

## 本地验证

- 类型检查通过，完整自动化测试 **120 / 120** 通过。
- 使用用户原始约 59 MB 的 HTML 完成 **550 / 550** 个顶层对象的重新解析及编译插件测试宿主导入，**0** 失败。
- 文件中的 **172** 个纯色路径图形全部转成 SVG，没有剩余的未支持裁剪警告；截图对应的首屏 **4** 个倒计时共 **8** 个轨道/弧线路径均已转换。
- 全部捕获节点的位置与尺寸保持一致，包括上一版恢复的原画布排布。总捕获节点仍为 **20,531**。
- 浏览器中将首屏的原 CSS 路径替换为实际生成的 SVG，圆环和中央数字视觉一致；按通道差值大于 24 统计的整屏像素差异约 **0.044%**，主要在曲线边缘。
- 验证覆盖填充规则、透明孔洞、半透明颜色、非正方形、缩放和未支持容器的内容保留。
- 编译插件使用 Figma API 测试宿主，浏览器截图对照为原 HTML 与生成的 SVG。尚未完成真实 Figma 客户端渲染验收。

原 HTML、捕获 JSON 和截图只保留在本地忽略的 `artifacts/icon-mismatch/` 中，不进入分发包。

## 重测

1. 关闭并重新运行 **HTML to Figma · Local**，确认底部为 **v0.9.2**。
2. 重新选择原 HTML，使用 **视觉还原** 并保持 **自动拆分多页面** 开启。
3. 点击 **解析并预览**，再导入所需页面。
4. 检查倒计时是否恢复为空心圆环，蓝色/橙色弧线与中央数字是否可见。

旧版捕获 JSON 没有这些裁剪路径，需要从原 HTML 重新生成；已导入的矩形不会自动更新。
