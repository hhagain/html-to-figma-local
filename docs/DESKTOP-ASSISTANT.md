# HTML to Figma 捕获助手

Windows x64 新增于 v0.8.0，安装和构建见 [Windows 助手指南](WINDOWS-ASSISTANT.md)。下文保留原生 macOS 版本说明。

v0.4.0 新增原生 macOS 桌面助手，将运行环境、本地服务和捕获浏览器一起打包。用户不需要安装 Node.js、npm 或 Playwright，也不需要在终端运行命令。

## 系统与交付形式

- Apple Silicon Mac（M 系列），macOS 14 或更高版本。
- `HTML to Figma Capture.app`：可直接运行的应用。
- DMG：打开后将应用拖入 Applications。
- ZIP：完整解压后运行，不能只拷贝应用内部的单个文件。
- 当前为 ad-hoc 签名的本地测试版，没有 Apple Developer ID 公证。正式公开分发前应使用自己的发布证书签名、公证；若系统阻止首次打开，应由用户在 macOS 提供的安全界面确认，不要关闭 Gatekeeper。

## 首次使用

1. 安装并打开 **HTML to Figma 捕获助手**。
2. 确认首页显示“捕获引擎已就绪”。
3. 点击“显示 Figma 插件”。助手会把兼容插件放到自己的应用数据目录，并在 Finder 中选中 `manifest.json`。
4. 在 Figma 桌面端选择 **Plugins → Development → Import plugin from manifest…**，选择该文件。
5. 运行插件，打开“网页链接”，点击“连接桌面助手”。
6. 核对插件与助手显示的六位配对码一致，在助手里点击“允许连接”。
7. 在助手中输入网页或本地 HTML 地址；多状态捕获默认使用“自动探索交互”，勾选结果后开始捕获。选择目标 Figma 文件/页面，再点击“直接导入 Figma”。需要精确步骤时可使用高级状态清单。

已经使用本仓库开发插件的用户，只需重新运行 v0.7.0 插件即可测试连接。需要稳定安装位置时，再从助手导出的目录加载 manifest。

## 日常使用

- 双击打开助手，然后在 Figma 插件中使用。配对凭据会保留，下次自动重连。
- 关闭助手窗口后，后台仍运行；可从 macOS 菜单栏图标重新打开。
- 菜单栏提供“捕获工作台”“显示 Figma 插件”“重新启动捕获服务”和“退出捕获助手”。
- 选择“退出捕获助手”会停止本次服务和由它启动的捕获浏览器。正在运行的捕获会取消，已导入的 Figma 图层保留。
- 助手不会自动开机启动。当前版本需要你在使用时打开一次应用。
- 助手导出或更新插件文件时，会保留已经由 Figma 分配的插件 ID。

## v0.7.0 直传与缩放

在桌面工作台勾选捕获结果，选择目标 Figma 文件/页面，点击“直接导入 Figma”；目标插件自动执行，无需第二次点击或 JSON 中转。完成、失败和取消状态会回传助手。

预览提供 10%–400% 手动缩放、100% 和适应窗口，支持 ⌘ + 滚轮缩放和空格 + 左键拖拽。详见 `DIRECT-HANDOFF.md`。

## v0.6.0 交互探索与渐变

多状态默认选择“自动探索交互”，无需准备 JSON，能够记录详情、弹窗、表单等状态。请核对探索报告中的失败、跳过和未处理项；所选状态成功不等于完整覆盖。详见 `INTERACTION-EXPLORATION.md`。

顶部背景发白与导航文字色块问题需要重新捕获并导入；已经生成的旧 Figma 图层不会自动改写。新增像素渐变、渐变文字和等比缩放字体转换。

## v0.5.1 多页预览

在桌面工作台完成多状态捕获后，可从右侧预览区翻页或选择页面，也可在左侧页面列表点“预览”。页码、页面名称与截图同步。升级前的任务需要重新捕获一次，才能获得所有页面的截图。

## v0.5.0 自动发现

更新到 v0.5.0 后，在“网页链接 → 多状态捕获”中直接粘贴网址或路径，点击“自动发现页面”，勾选后点击“开始捕获”。页面来源默认自动发现；需要精细控制时切换到“状态清单（高级）”。

本地路径可省略 `file:///`，也可写 `Users/用户名/Design%20Project/index.html#/dashboard`。助手会补全本机绝对路径。详见 `AUTO-DISCOVERY.md`。

## 更新与本地 HTML

1. 退出旧助手，打开 v0.7.0 应用。
2. 点击“显示 Figma 插件”，更新助手导出的插件文件；已有 manifest 路径不变。
3. 关闭并重新运行 Figma 插件，确认底部显示 `v0.7.0`，连接会自动恢复。
4. 在“网页链接 → 当前页面”的页面地址中粘贴完整本地地址，例如 `file:///Users/yourname/Design%20Project/index.html#/dashboard`。
5. 点击“解析并预览”，检查预览后点击“导入到 Figma”。

可以保留 `%20` 等编码，也可以粘贴含空格的完整 file 地址。`?query` 和 `#/route` 都会保留。多状态捕获使用相同入口，状态中的 `url` 可写 `#/ledger`、`#/assets` 或同目录下的另一个 HTML 相对路径。

助手只映射入口 HTML 所在目录及子目录中的资源，映射仅存在于本次捕获浏览器内，没有新增文件分享端口。目录外资源、隐藏文件及逃逸目录的符号链接不会被读取。入口需为实际存在的 `.html` / `.htm` 文件；资源单文件限制 32 MB。需要相对引用的 CSS、JS、图片等应和 HTML 一起保留在项目目录内。

页面的 JavaScript 会执行，但不继承 Open Design 或日常浏览器的 localStorage、Cookie 或登录状态；源页面内置的示例数据仍会正常运行。纯前端 hash 路由可以直接捕获；依赖后端 API、构建开发服务或目录外资源的项目仍需对应服务运行。

应用图标与首页使用 `desktop/resources/app-icon.png`，菜单栏使用该图标的系统单色模板。原始素材为 128×128 透明 PNG，应用打包时等比居中生成多尺寸图标，不裁切、不改变配色。

## 连接机制

服务仅监听 `127.0.0.1`。默认使用 3847；被旧服务占用时尝试 3848–3851，Figma 插件自动发现，无需输入端口。

发现接口只返回产品信息，不返回调用凭据。首次连接必须在助手窗口确认匹配的配对码；插件保存自己的随机凭据，助手只持久化其哈希。拒绝、过期或未经确认的请求不能调用捕获接口。

“手动连接（开发模式）”保留兼容旧命令行服务，桌面助手用户不需要使用。助手首页可复制临时手动连接码，重启后该码会变化；已配对的插件不依赖此临时码。

## 捕获边界

- 网页捕获运行在应用内置的独立 Chromium 中，不继承你日常 Chrome 的登录状态。
- 多状态默认可自动发现并勾选页面，见 `AUTO-DISCOVERY.md`；复杂交互使用 `DYNAMIC-STATES.md` 的高级清单，不会自动穷举所有输入组合。
- 多状态引擎默认阻止网络写请求。依赖真实登录 POST、跨域 OAuth 等流程的网站不属于当前示例模式覆盖范围。
- Figma 中生成的是静态可编辑图层，不包含原页面的运行逻辑。
- `.fig` 原生文件仍由 Figma 的 Save Local Copy 导出；助手生成的 `.h2f.json` 供插件导入。

## 数据位置

应用数据位于用户的 `~/Library/Application Support/HTML to Figma Capture/`：

- `paired-clients.json`：已确认客户端的标识和凭据哈希。
- `Figma Plugin/`：从助手导出的开发插件。
- `service-state.json`：当前服务的进程与地址信息，不含调用凭据。

助手使用浏览器临时上下文；没有自动删除用户原始 HTML、Figma 文件或其他下载文件的功能。

## 开发构建

```bash
npm run desktop:build
npm run desktop:package
```

构建机需要 Apple Command Line Tools、独立 Node 二进制和 Chromium Headless Shell。可通过 `H2F_NODE_BINARY`、`H2F_BROWSER_DIR` 指定来源。构建脚本会拒绝依赖 Homebrew 路径的 Node 二进制，防止产物只能在开发机运行。

原生界面使用 Objective-C / AppKit / WKWebView，通过私有 stdin/stdout 管道管理内置 Node 服务。采用 `-fno-modules` 编译，以避免本机 Swift 模块映射冲突，不修改系统工具链。

内置运行环境、浏览器和第三方依赖的许可证保留在应用包中。缺少 Apple 发布证书时仅做本地 ad-hoc 签名。
