# 设计稿输出：页面模板与组件状态（v0.13.0）

自动探索的默认目标是给设计师提供可编辑的代表页面和组件清单。它与逐条记录动态产品所有数据状态有不同的输出规则。

## 使用方法

1. 更新助手与 Figma 插件到 v0.13.0。
2. 选择“网页链接 → 多状态捕获 → 自动探索交互”。
3. 输出内容保持“设计稿 · 页面模板＋组件状态”。
4. 探索后查看“页面模板 / 组件状态”数量，勾选需要的项目并捕获。
5. 页面模板保持页面尺寸；组件按局部区域尺寸捕获和预览。
6. 导入 Figma 后，模板为可编辑 Frame，组件为原生 Component，同一组件的多个状态组成 ComponentSet。

例如只改变金额和日期、其余结构一致的统计页，默认输出一个页面模板，并最多保留两个统计卡片的数据组件样本。展开筛选器后可多输出一个完整的展开页面，同时把筛选器的默认、展开、填写等变化放在组件清单中。空白、校验和选中状态不会因为金额不同而分别复制完整页面。

## 归并规则

- 页面身份参考同源路由、主导航和主标题；页面布局参考 DOM 骨架、显示方式、主要排列和展开/弹窗信息。
- 金额、日期、用户输入及普通数据文案与完整状态校验分开处理。同一结构的数据变化复用模板。
- 功能区域参考 section、article、form、details、region、dialog 和常见 card/panel 容器；跳过包含主内容区的手机外壳。
- 组件状态参考局部结构、展开、填写、校验、禁用、选中、内部滚动与主要视觉样式。嵌套区域优先保留实际改变的局部，减少整卡重复。
- 遍历同一结构时仍检查新出现的控件。设计稿模式会按布局和局部控件状态复用已处理的动作，减少在数据组合上反复探索。
- 捕获依然重放原始步骤并校验完整状态摘要，不能稳定重放的条目会失败，不用另一条数据冒充成功。

探索结果显示观察状态数、页面模板数、组件状态数和减少的整页重复。页面数下降表示输出归并，并不表示完整业务交互覆盖。

## 数据样本与全部状态

“探索设置 → 同样式的数据样本”可选择：

- 合并：不为纯数据变化生成额外组件；真正的视觉和交互状态仍保留。
- 最多 2 个样本（默认）：保留初始和一个数据变化示例。
- 最多 3 个样本：多保留一个数据示例。

样本数按组件的同一种结构和视觉状态计算，输入后、错误、空态等状态分别判断，不将所有文案组合穷举成组件。组件数据仍可在 Figma 内编辑。

选择“全部交互状态 · 调试用”时沿用旧版逐状态输出。输出方式和数据样本数改变后需重新探索，不能继续沿用不同规则的旧会话。时间、深度和每轮动作预算以及继续探索功能保持可用。

API 的 `POST /api/discover` 接受 `outputMode: "design" | "states"` 和 `dataSamples: 0..10`。默认是 `design` 和 `2`。结果和状态清单的 `artifact` 记录类型、组件家族与状态；捕获后的 `source.artifact` 随 JSON 与桌面直传保留。

## 识别边界

自动识别依据结构与控件证据，不能理解所有业务语义。无语义容器、Canvas 内部场景、复杂自绘控件、纯 CSS 动画和虚拟列表等可能需要补充状态清单或使用全部状态模式。可用 `data-h2f-component="组件名称"` 明确标注功能区域。

每个页面身份默认只保留一个展开/弹窗的完整上下文；其他展开组合放在组件变体中。路由、主导航和真正的整页布局不同仍保留必要模板，因此整个产品不限制为固定两张。目标是去掉数据重复，同时保留设计师需要的结构和组件状态。旧 Figma 图层不会自动整理，旧 JSON 也缺少局部 DOM 与探索关系，需要从原 HTML 重新探索和捕获。

原生组件组合失败时保留独立可编辑组件并给出转换说明，不删除已完成的页面。自动化的 Figma API 测试宿主不替代真实 Figma 客户端的最终渲染验收。
