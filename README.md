# HTML to Figma · Local

把本地 HTML 或浏览器页面转换为可编辑的 Figma 图层。包含 Figma 开发插件、本地捕获工作台和命令行工具。

当前版本：**0.15.0 开发版**。代码已独立实现；参考了 HTML → 布局数据 → Figma 的工作流，没有复制 Neil Studio 的插件代码或界面。

## v0.15.0 手动操作原网页并标记

在助手的“网页链接 → 多状态捕获 → 手动操作原网页并标记”中，自行点击、输入、滚动原 HTML，标记并勾选需要的页面。每条标记可独立选择“当前页面”或“完整长页”，保存当时的可编辑图层，切换页面后仍可调整范围。

“整理其余已浏览状态为组件和图标”是独立开关。导出排版可选“按勾选顺序”或“智能排版”，重新勾选的页面排到最后。生成后可下载 JSON、发送到插件或直接导入已连接的 Figma 文件。详见 [手动标记使用说明](docs/MANUAL-CAPTURE.md)。

## v0.14.0 页面优先、单一代表组件与图标库

设计稿模式先发现主导航及页面入口，再探索组件分支；主导航不受同类控件取样数量限制，报告显示已验证和待探索的主导航。捕获顺序为页面模板、组件状态、图标资源。

相同结构的列表项跨 DOM 位置复用一个代表组件，图标、文案与数据颜色不再拆出多个组件家族。展开、填写、选中、禁用及错误反馈继续作为局部组件状态。同一个表单或弹窗只保留一个完整页面，字段值、支付方式与校验提示不再复制整页。

默认将数据合并为一个代表组件，页面和组件中使用的图标按图形去重并集中到“图标库”。SVG 保留矢量，图片保留原资源形式。详见 [页面优先与组件目录](docs/PAGE-FIRST-CATALOG.md)。

## v0.13.0 面向设计的页面模板与组件状态

多状态捕获默认选择“设计稿 · 页面模板＋组件状态”。相同布局的金额、日期、列表记录和文案变化复用一个页面模板；展开与弹窗等页面布局保留代表模板，输入、校验、空态、选中等局部变化整理到组件清单。相同组件样式默认最多保留两个数据样本，其他数据不再生成整页。局部组件按自身尺寸捕获，导入后为原生组件，同一组件的多个状态组合为变体集。

可在“探索设置”调整数据样本数，或选择“全部交互状态 · 调试用”恢复逐状态输出。切换输出方式需要重新探索；旧捕获数据无需强制改变。自动识别采用页面结构、功能区域与控件状态，不是业务语义模型。详见 [设计稿输出说明](docs/DESIGN-OUTPUT.md)。

## v0.12.0 探索设置、继续探索与图表修复

“探索设置”提供推荐、深入和无总上限预设。深度、每轮尝试次数、每轮时长与每轮新增状态数都可自定义，填 `0` 或 API 中传 `null` 表示该项不限。“遍历已识别的控件与选项”移除代表样本的同类控件、下拉选项与每状态候选数量限制；表单仍使用示例输入，队列处理完成不等于穷举所有业务条件。

停止或达到预算后点击“继续探索”，会沿用已记录状态、去重信息和未处理路径。提高深度后会继续深层动作；从代表样本切换到遍历控件会补查之前的状态。详见 [探索设置与继续探索](docs/INTERACTION-EXPLORATION.md)。

修复 SVG 环形图的 `pathLength` 虚线长度与 CSS 内部变换转换，避免占比圆环被切成重复小段。单张长页仅展开页面主滚动区，卡片、列表和弹窗保留原尺寸、裁切和内部滚动位置；关闭的折叠区保持关闭。内部滚动位置不同的状态不会被当作同一长页合并。需要更新助手及插件，并从原 HTML 重新捕获。

## v0.11.0 单张长页与智能排版开关

捕获工作台新增两个独立选项：**单张长页**将当前已加载的滚动区域展开为一个可编辑长 Frame，合并同一状态的滚动重复，并保留一次顶部与底部控件；**智能排版**控制按模块、页面层级和功能状态分区，关闭时按普通网格排列。两者默认开启。

智能排版可在捕获后调整，无需重新捕获，设置随 JSON 备份与桌面直传保留。单张长页需要从原 HTML 重新捕获；虚拟列表和无限滚动仅包含已加载内容，超大内容继续受图层和尺寸预算约束。见 [长页与排版选项](docs/LONG-PAGES.md)。

## v0.10.0 产品页面自动分类与分组排版

动态探索和状态捕获现在保留页面来源、主导航、功能区域和滚动关系。导入 Figma 时按模块生成有名称的 Section，分列展示一级页面、二级页面和功能页面。同一长页的不同滚动位置按顺序相邻放置，同一详情模板的不同记录及同一弹窗的填写/校验状态归组。原 HTML 大画布继续优先保留原坐标。

分类依据导航、页面路由、弹窗和控件所属区域进行推断，未识别的层级显示“待确认页面”。捕获后的页面列表支持调整整组层级；分类随 JSON 备份和桌面直传保留，无需手写状态清单或额外 AI 服务。详细规则、操作与验证范围见 [产品页面分组](docs/DESIGN-ORGANIZATION.md)。

需同时更新桌面助手和 Figma 插件，并重新探索/捕获；旧数据缺少进入关系时不会猜测成确定层级。

## v0.9.3 outline 输入框描边修复

修复使用 CSS `outline` 绘制的输入框和按钮轮廓未被捕获、白色控件融入白色背景的问题。常见轮廓转换为 Figma 原生内侧/居中/外侧描边，不改变内容框和 Auto Layout 尺寸；特殊偏移及同时存在 border 的简单容器使用独立轮廓层保留外观。

适用于视觉还原与 Auto Layout 两种模式，需要从原 HTML 重新解析。原因、验证范围与步骤见 [输入框 outline 修复](docs/OUTLINE-FIELDS.md)。

## v0.9.2 CSS 路径图标修复

修复倒计时圆环、剩余弧线等由 `clip-path: path(...)` 绘制的纯色图形导入后变成实心方块的问题。符合条件的路径转为可编辑 SVG，保留空心、填充规则、颜色和缩放；中央数字保持可编辑文字。图形外层清除矩形背景，避免再次遮挡圆环内部。

从原 HTML 重新解析后生效。当前支持无子内容、无边框、无圆角和阴影的纯色 `path()` 图形，其他裁剪明确提示。原因、重测步骤与验证范围见 [CSS 路径图标修复](docs/CLIP-PATH-ICONS.md)。

## v0.9.1 保留 HTML 原画布排布

修复绝对定位设计画布在自动拆页后被重新按网格排列的问题。同一父画布中的绝对定位页面、色板、标题、页签和注释现在记录原始坐标，逐页导入后保持相对位置与间距；只勾选部分页面也不会压缩原有空隙。不同 HTML 文件分别放置，普通独立页面继续自动排列。

更新插件并从原 HTML 重新解析即可生效；旧版 JSON 没有原画布坐标，需要重新生成。原 HTML 已有的重叠会原样保留。捕获数据仍兼容 v1，说明和验证范围见 [原画布布局修复](docs/CANVAS-LAYOUT.md)。

## v0.9.0 取消 200 页上限

文件/代码中的多页 HTML、多个源文件、捕获 JSON、状态清单、预览及 Figma 逐页导入不再按 200 页或 200 个文件拒绝。保留每页校验与整批资源预算，按顺序创建 Frame，支持取消并保留已完成页。

自动发现默认没有固定页数上限，仍遵守扫描、时间、操作及同源范围；调用 API 时可以显式传入正整数 `maxPages` 设置任务预算。预算与导入能力分开处理。

## v0.7.0 桌面直传 Figma 与预览缩放

在桌面助手捕获并勾选页面后，选择已连接的 Figma 文件和页面，点击“直接导入 Figma”即可完成导入，无需切到插件再次点击，也无需下载 JSON。插件需要在目标文件中保持运行。目标发生变化会停止本次导入，完成数、失败和取消状态会回传助手。“发送到 Figma 插件”保留为手动接收方式。

## v0.6.0 自动交互探索与顶部渐变修复

多状态捕获默认使用“自动探索交互”：无需输入状态 JSON，助手会在独立浏览器会话中打开导航、详情、弹窗、表单、折叠区域及代表性滚动位置，记录可重放步骤后供你勾选捕获。可导出工具自动生成的清单和探索报告。轻量的“仅发现导航页面”仍保留。

界面区分已记录状态、重复状态、失败操作、跳过控件和待探索动作，不把“所选页面捕获成功”解释为完整覆盖。默认按 300 次尝试、3 分钟和 4 层深度探索；这些预算均可配置或取消，并可保留进度继续探索。详见 [自动交互探索](docs/INTERACTION-EXPLORATION.md)。

修复 CSS 线性渐变中的像素色标，支持混合百分比、像素和双位置色标，使用缩放前尺寸换算；`background-clip: text` 保留为可编辑渐变文字，避免导航文字变成矩形色块；等比缩放后的字号与行高同步换算。

## v0.5.1 多状态页面预览

桌面工作台不再只显示第一张截图：预览区提供上一页、下一页、页面下拉选择及“当前页 / 总页数”，也可在左侧捕获页面列表点击“预览”。查看页面与导入勾选独立。每页截图按需加载，浏览器最多缓存 3 页，支持大批次逐页浏览。

## v0.5.0 自动发现与路径简写

现在可以直接选择“网页链接 → 多状态捕获 → 自动发现页面”，输入网址或本地 HTML 路径，点击“自动发现页面”，勾选结果后点击“开始捕获”，无需准备 JSON。状态清单保留为高级选项。

支持 `Users/yourname/Design%20Project/index.html`、`/Users/yourname/Design Project/index.html`、`file:///…/index.html`，可带查询参数和 `#/dashboard`。单页、自动发现和高级清单使用相同的地址解析。

自动发现收集同站页面链接、导航标签与本地目录的 HTML，不再固定最多 200 页；首次检查最多 30 页、导航深度 2、60 秒，其余候选在捕获时验证。复杂弹窗、表单分支和登录过程需要高级清单补充，不保证枚举所有交互组合。详细操作见 [自动发现说明](docs/AUTO-DISCOVERY.md)。

## v0.2.1 自动布局修复

修复选择“智能 Auto Layout”后按钮高度被压缩、底部内容上移、弹窗位置改变的问题。启用 Figma 自动布局会立即重算容器尺寸；新版在设置固定尺寸与布局参数后，恢复捕获到的宽高，并核对直接子图层的位置和尺寸。超过 1.5 px 的差异会使该容器恢复为视觉布局，并在转换说明中提示。

旧版本已导入的图层不会随插件更新自动修复。关闭并重新运行插件，确认底部显示 v0.2.1，再从原 HTML 重新导入。

## 快速使用

仓库中已包含构建好的 `dist/`。只使用 Figma 插件时不必安装 Node 依赖。

1. 打开 **Figma 桌面客户端**和一个用于测试的设计文件。
2. 在菜单中选择 **Plugins → Development → Import plugin from manifest…**。
3. 选择本项目根目录的 **`manifest.json`**，保持旁边的 `dist/` 目录不变。
4. 运行 **HTML to Figma · Local**。
5. 拖入一个多页 HTML、批量选择多个 HTML，或粘贴 HTML。默认开启“自动拆分多页面”。
6. 点击“解析并预览”，检查页面列表、尺寸和转换说明。
7. 勾选要导入的页面，再点击“导入到 Figma”。每页生成独立 Frame；同一绝对定位画布保留原坐标，普通独立页面自动排列。

单页生成一个根 Frame；多页生成多个独立 Frame。多页按顺序导入，当前页失败或取消时清理当前页的半成品，已完成页面保留。失败页会记录原因，其他页面继续。取消后可在同一次插件会话中继续导入未完成页面。

> 已在真实 Figma 桌面端完成用户提供的四屏登录设计导入，以及 200 页压力测试：200 / 200 页完成、0 页失败，处理 10,200 个捕获节点、4,800 段文字。此结果证明所测样例可用，不代表任意复杂网页都能像素级还原。

## 多页批量导入步骤

1. 在文件入口拖入包含多个页面的 HTML，或一次选择多个 `.html` / `.htm` 文件。
2. 保持“自动拆分多页面”开启。默认识别顶层 Pencil `data-pencil-name`、`data-artboard`、`data-page`、`.page`、`.slide`、`.artboard`。
3. 如果导出工具使用其他标记，在“页面选择器”中填入 `.screen` 等实际选择器。“捕获区域”用于限定搜索范围，默认 `body`。
4. 点击“解析并预览”，确认识别出的页数及各页尺寸，再勾选需要导入的页。
5. 点击“导入到 Figma”。界面显示当前页、逐页结果和完成/失败计数；每页都可独立编辑。
6. 需要停止时点击“取消”。已完成页面保留，可在插件仍打开时继续导入剩余页；失败页可重试。

“页面”在这里指 HTML 中的屏幕/设计稿，导入为**同一个 Figma Page 中的独立 Frame**，不会为每张导入稿创建左侧 Pages 条目。

- 如果要保留单个 HTML 的整张大画布，关闭“自动拆分多页面”。
- 对四屏登录设计，默认会识别为 4 个 `390 × 844` Frame；整画布模式可用浏览器宽度 `1740`、捕获区域 `body > div` 得到 `1740 × 844`。
- 页面状态只保留在当前插件会话；关闭/重开插件不会恢复上次队列。再次加载同一文件时请自行避开已经导入的页面。
- 多页 JSON 使用 `format: "h2f-bundle"` 和共享资源表。重复图片只存一份，向 Figma 每次只发送一页数据。
- URL 入口可选择单次捕获或多状态捕获；动态状态清单也不再按 200 个状态拒绝。多静态文件仍使用文件/代码入口。

### 批量限制

不设固定页数上限；每批最多 **120,000 个捕获节点**；共享图片去重后最多 **64 MB / 2000 个资源**。每页仍保留 6000 节点和 24 MB 图片预算。所选文件总量最多 128 MB。超过限制会明确报错或记录未完成页，不会把超过限额的部分静默当作成功。

## 三种入口

### 1. HTML 文件 / 代码

- 直接拖入 `.html`、`.htm`，或粘贴完整 HTML。
- 输入浏览器宽度（320–3840 px）；默认 1440 px，内部视口高度为 900 px。
- 用 CSS 选择器选择区域，例如 `body`、`.dashboard`、`#app`。
- 有相对图片、样式或字体路径时，填写“资源基础地址”，如 `https://example.com/design/`。
- 识别到 Tailwind Play CDN 时，会使用随插件打包的 Tailwind 3.4.17 在本地编译静态类名、任意值和字面量配置，不依赖 CDN 网络。支持 `text/tailwindcss` 中的 `@apply`。
- 不执行原始页面脚本。Tailwind 动态函数配置、外部插件，以及 React / Vue / JavaScript 动态页面请启动其开发服务器，再使用 URL 捕获。
- 对含本地 CSS / 图片的完整目录，推荐下面的本地服务或 CLI，保留资源相对路径。

### 2. 网页 URL

桌面助手用户可以直接连接助手，跳过下面的命令行步骤。手动开发环境需要 **Node.js 22+** 与 Chrome / Chromium。

```bash
npm ci
npm run build
npm run serve
```

服务会打印工作台地址与连接码：

```text
捕获页面：http://127.0.0.1:3847
连接码：每次启动随机生成
```

打开工作台可直接捕获 URL 并下载 `.h2f.json`。在 Figma 插件中使用 URL 入口时，把连接码粘贴到“本地服务连接码”，点击“检测”后捕获。

捕获会启动一个独立的无头浏览器，不使用用户现有浏览器的 Cookie 或登录状态。登录页、验证码、反爬限制等页面不保证可捕获。

服务默认提供 `examples/` 中的示例：

```text
http://127.0.0.1:3847/source/dashboard.html
```

要捕获自己的本地项目目录：

```bash
npm run serve -- --root /absolute/path/to/html-project
```

然后在 URL 入口输入：

```text
http://127.0.0.1:3847/source/index.html
```

服务只监听 `127.0.0.1`。捕获 API 需要连接码，且不提供任意文件路径读取接口。`--root` 是允许提供静态资源的目录，默认仅为 `examples/`。插件默认连接端口为 3847；自定义端口适合独立浏览器工作台使用。

如果没有可用 Chrome：

```bash
npx playwright install chromium
```

也可设置 `H2F_CHROME_PATH` 指定 Chrome 可执行文件。服务每次重启会更换连接码，插件内需要重新填写。

### 3. 命令行 / 捕获数据

```bash
npm run capture -- --file examples/dashboard.html --width 390 --output artifacts/mobile.h2f.json
npm run capture -- --url https://example.com --width 1440 --selector body --output artifacts/page.h2f.json
```

输出便携的 `.h2f.json` 和 JPEG 预览。把 JSON 拖入 Figma 插件即可导入，不需要在 Figma 内重新访问目标网页。

本项目使用版本化的 `schemaVersion: 1` 数据格式。之前 GitHub 示例中的 `layout.json` 格式不兼容；请重新捕获。

## 支持范围

| 内容 | 当前行为 |
|---|---|
| 多页面 | 自动拆分、批量选择 HTML、页面勾选、逐页进度、失败隔离和当前会话内继续导入 |
| Tailwind | 本地编译 Tailwind 3 静态配置与类名，保留 Pencil 中文图层名称 |
| 页面尺寸 | 读取真实视口与区域尺寸，不固定为 1920×1080 |
| 文本 | 保留中文、字号、字体族、字重、斜体、行高、字距、颜色和下划线/删除线 |
| 换行与富文本 | 按浏览器实际文本行与样式段创建可编辑文字；一个段落可能对应多个 Text 节点 |
| 图片 | 图片内嵌到 JSON；跨域图片可由本地捕获服务获取；失败时显示占位并报告 |
| SVG | 内联 SVG 和符合条件的 CSS path 纯色图形用原生矢量导入；SVG 图片作为位图导入 |
| 背景与边框 | 纯色、基本线性渐变、圆角、边框和基础内外阴影 |
| Flex | 视觉模式保留位置；Auto Layout 模式只升级几何一致的简单容器 |
| Grid | 保留浏览器中的实际位置；不转换为 Figma Grid 布局 |
| Canvas | 可读取时转换为位图，并注明内部内容不可单独编辑 |
| Input / Textarea | 保留静态外观与文本；不生成交互组件；密码值遮蔽 |
| 警告报告 | 字体替代、缺失图片、SVG 失败、部分不支持效果、Auto Layout 降级 |

### 两种布局模式

- **视觉还原（默认）**：所有子层使用捕获到的位置。适合初次导入和高保真静态快照。
- **智能 Auto Layout**：只转换没有换行、反向排列、绝对定位子项、外边距等复杂情况，且捕获几何能与 Figma 固定尺寸模型匹配的 Flex 容器。其他容器自动保留视觉位置，并给出说明。转换后还会核对 Figma 实际尺寸与位置；如果发生偏移，该容器会恢复到转换前状态。

Auto Layout 不代表已生成组件库、变量、响应式约束或交互原型。

## 已知限制

- 已完成所列样例的真实 Figma 测试；没有与 Neil Studio 插件进行还原率对照，也没有覆盖所有网页和字体组合。
- CSS 伪元素、旋转/倾斜、复杂变换、滤镜、背景模糊、复杂 clip-path（纯色叶子 path 图形已支持）、复杂层叠、混合模式等不完整支持。可检测的情况会提示。
- 径向/锥形/重复渐变、多色边框、复杂背景定位不完整支持。
- Shadow DOM、iframe 内部页面、视频、交互状态和事件不会还原。
- 文字是逐行可编辑快照；修改长段落后不会自动重现网页段落重排。
- 字体取决于 Figma 当前可用字体。缺失时选择候选字体并报告，不会安装或向 Figma 上传字体。
- 远程字体、图片和样式可能受跨域、授权或网络条件影响。文件解析在本地进行，但引用的远程资源仍会向其原始服务发起请求。
- URL 捕获只获取当前加载状态；无限滚动、需要点击展开、持续更新或延迟很久的内容不保证完整。
- 浏览器预览保持固定 900 px 高度，内部可滚动；超长网页的服务端预览可能只显示首屏，JSON 捕获区域独立计算。
- 每页限制约 6000 个节点、250000 个字符、300 个图片资源、24 MB 内嵌图片；整批限制见上方。复杂长页请用选择器分区捕获。

```bash
npm run typecheck
npm test
npm run package
```
